# 演示：一句话 → 机器人自己走

> 目标：**一条命令起栈**、**一条命令讲完整段故事**。
> 讲的是：*规划 → 每一步各自过网关 → 车动 → 被挡住 → **没有人再说话，Agent 自己换了一条走法** → 走通*。
>
> ⚠️ 演示**不是验收**。判定在 `tools/agent_ground_acceptance.py`（真机）
> 与 `tools/llm_planner_acceptance.py`（接口与失败路径）里。

---

## 1. 两条命令

```bash
# ① 起栈（一条命令，七个节点；**不含厂商栈** —— 厂商栈要先在跑）
ros2 launch embodied_bringup demo.launch.py

# ② 讲那段故事（另一个终端）
python3 tools/demo_run.py --text "往前走被挡就绕开"
```

**默认不开真动**：`dry_run=true`、`allow_motion=false` ⇒ 故事的每一步都照跑，
**只有车不动**（命令停在 `/embodied/motor/cmd_vel_dryrun`）。
⚠️ 演示脚本**开头就会把这件事打在屏幕上**（它读 Motor Driver 状态里的 `dry_run` 位）。
上一次真机验收就是被它揪出了一个 bug：脚本把 `dry_run` 读错了下标，
于是"干跑的车被报成会动"—— 而那次车**一动没动**（见 `DEV_NOTES` 坑 42）。

## 2. 要真动（**车边必须有人、手能直接断电**）

```bash
ros2 launch embodied_bringup demo.launch.py \
    dry_run:=false allow_motion:=true \
    llm_enabled:=true \
    llm_base_url:=https://api.deepseek.com/v1 llm_model:=deepseek-flash \
    llm_api_key_env:=DEEPSEEK_API_KEY        # 密钥从环境变量读，不进仓库
```

⚠️ 本机**没有物理急停**（#22）。车能停住的证据汇总见 `PROJECT_STATUS.md` §4.1。
⚠️ 厂商的 `voice_control_move` 挂着**无限幅**的 `/controller/cmd_vel`（#26），
**运动前要停掉它**（厂商栈一重启它就会回来）。

## 3. 摆位决定你能看到**哪一拍**

故事的看点是"被挡住之后自己换路"，而**它只在受阻时才发生**：

| 前方参照面（原始 `/scan`） | 会看到 |
|---|---|
| **< 受阻阈值**（规则表示例 0.5 m；真模型每次自己定，**策略上限 1.0 m**） | ★ **被挡住 → 自己换一条路** 那一拍 |
| **> 1.0 m** | 一路走通（`ARRIVED`）—— **不可能出现 `BLOCKED`**（阈值封顶 1.0 m） |

⇒ **想演"脱困"，把车摆到离障碍 1 m 以内、越近越好**；想演"一路通畅"，就让它前方开阔。
演示脚本开头会把当前读数报出来，并说清怎么摆能看到那一拍（**只提示，不拦**）。

## 4. 离线能演到哪、真模型才能演到哪（**这条最容易讲错**）

| | 规则表（离线） | 真模型 |
|---|---|---|
| 一条计划分几步执行、每步各自过网关 | ✅ 能演 | ✅ 能演 |
| 某步报 `BLOCKED`、计划**继续下一步** | ✅ 能演 | ✅ 能演 |
| **被挡住后自己换一条走法**（D-044 重规划） | ❌ **演不了** | ✅ 能演 |
| 一句话随便说（不在表里也认） | ❌ 只认表里的句子 | ✅ 能演 |

**为什么规则表演不了重规划**，这一条值得讲给观众听：
规则表是**查表**，同一句话**只有同一个答案**；重规划再问一次，拿回来的还是同一条计划，
于是**被"新计划必须与试过的不一样"当场挡掉**，任务收尾并说明原因 ——
**这是正确结局**（要别的走法，得先把那条规则改掉），不是坏了。

⇒ 演示时**两条路各演一遍**效果最好：先用规则表演"多步编排"（离线、确定、快），
再开真模型演"自己想出脱困计划、被挡后换路径"。

## 5. 你会看到什么

```text
  🗣 你说：往前走被挡就绕开
  📏 摆位：正前方参照面 0.41 m（原始 /scan）
  ① 规划好了 ✅  已受理并派发 autonomous.advance_until_blocked
                （共 3 步，第 1 步已派发；来自 规则表；处于 WAIT…）
  ② 执行
     → 第 1 次派发：autonomous.advance_until_blocked
       ■ 前方受阻 —— ⚠️ 对这个计划来说这是**正常结局**，不是失败
     → 第 2 次派发：autonomous.turn_until_clear
       ✓ 完成
     → 第 3 次派发：autonomous.advance_until_blocked
       ✓ 完成
  ③ 车到底动没动（独立基准：原始 /scan 与 IMU）
```

⚠️ **"前方受阻不是失败"这句话是演示里最该讲清的**：对脱困计划来说，
`BLOCKED` 是第 1 步**正常的**结局（D-043 的推进规则就是为它定的）。
把它讲成"撞墙了"，观众记住的就是错的东西。

## 6. 机器人在整个演示里从不被大模型直接控制

值得当众说清的三件事：
1. **LLM 只做规划，不进控制环**：它给出的是**技能名 + 参数**，
   参数还要过注册表的策略上限、过网关的六项检查（D-029）、
   再被 Motor Driver 限幅（±0.2 m/s / ±0.5 rad/s）。
   `control.*` 这类底层原语**它碰不到** —— 红线在代码里，不靠它自觉（D-003 / D-035）。
2. **安全层有最终否决权**：演示里若有人在车头 0.30 m 以内，守卫会**锁存并让底盘停住**
   （2026-10-09 真机验过一次，人是真的）。这时技能如实报 `FAILED`、
   计划中止 —— 安全层刚介入，Agent **不会**自己找条新路继续走。
3. **停车不靠"我发了零就算数"**：Motor Driver **自己读**安全层状态并输出零，
   而且**持续主动发零**（本机底盘没有指令超时保护，D-020）。
